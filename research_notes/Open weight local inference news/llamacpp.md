## What shipped from August through November 2026 (speculative decoding, prompt cache, slots, vision, backends)

### Takeaway

llama.cpp is a C/C++ local LLM and VLM engine on ggml, with Metal, CUDA, and Vulkan as first-class GPU backends. From August to 28 October 2026 the stable line moved from the start of semver (v0.2.0) to v0.8.0. Speculative decoding is a server feature with an explicit `--spec-type` list that includes MTP; prompt caching is on by default; vision is the multimodal (`mtmd` / `--mmproj`) path, not a separate product.

### Inferences

- For a Linux or Windows box, the practical GPU choices in official binaries are CUDA (NVIDIA; Linux CUDA 12.8 or 13.4, Windows CUDA 12.4 or 13.4) or Vulkan (vendor-neutral GPU). Metal is the Apple path and is not how you run the Linux/Windows GPU builds.
- MTP is not a single switch. It is one value of `--spec-type` (`draft-mtp`), and release notes add it per architecture (GLM-4.5-Air in August, Qwen4Exp and GLM5-Next in October, Mellum2.1 in v0.8.0). A model without a matching draft head does not get MTP just because the server binary is new.
- Prompt cache and parallel slots are server features with defaults (cache on, slot count auto), not things an operator must compile in.

## The server binary and the OpenAI routes

### Takeaway

The current server binary is `llama-server` (Windows: `llama-server.exe`). The root README’s user-facing command is `llama serve`. There is no current doc that still tells you to build a target named `server`. It implements `/v1/chat/completions`, `/v1/embeddings`, and chat tool calls. Context is `-c/--ctx-size`, slots are `-np/--parallel`, and API keys are optional `--api-key` / `--api-key-file`.

### Cited Findings

- CMake target and path, from the server README: `cmake --build build --config Release -t llama-server`. “Binary is at `./build/bin/llama-server`.” Quick start: `./llama-server -m models/7B/ggml-model.gguf -c 2048` and `llama-server.exe -m models\7B\ggml-model.gguf -c 2048`. “The above command will start a server that by default listens on `127.0.0.1:9931`.” Root README quick start is the wrapper: `llama serve -hf ggml-org/Qwen3.5-0.8B-GGUF` under the heading “Launch OpenAI-compatible API server.” Tools index links the server doc as `[server](tools/server/README.md)`. — [tools/server/README.md](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md), [README.md](https://github.com/ggml-org/llama.cpp/blob/master/README.md)
- Dev doc, two modes: “Inference mode: The default mode for performing inference with a single loaded GGUF model.” “Router mode: Enables management of multiple inference server instances behind a single API endpoint. Requests are automatically routed to the appropriate backend instance based on the requested model.” — [tools/server/README-dev.md](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README-dev.md)
- Feature list (server README): “OpenAI API compatible chat completions, responses, and embeddings routes”; “Anthropic Messages API compatible chat completions”; “Function calling / tool use for ~any model”; “Speculative decoding”; “Easy-to-use web UI.”
- OpenAI and related routes named as headings in the raw server README: `GET /v1/models`; `POST /v1/completions`; `POST /v1/chat/completions`; `POST /v1/chat/completions/control`; WebSocket `/v1/realtime` (“Realtime transcription”); `POST /v1/responses`; `POST /v1/embeddings`; `POST /v1/messages` (Anthropic); `POST /v1/systemone`. Native routes include `POST /completion`, `POST /embeddings` (explicitly “non-OpenAI-compatible”), `POST /tts`, `POST /infill`, `GET /slots`, `GET /metrics`, `GET /props`. — [tools/server/README.md](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)
- Embeddings constraint, quoted: “This endpoint requires that the model uses a pooling different than type `none`. The embeddings are normalized using the Eucledian norm.” Flag: `--embedding, --embeddings` “restrict to only support embedding use case; use only with dedicated embedding models (default: disabled)”. Pooling flag: `--pooling {none,mean,cls,last,rank}`. — same README
- Tools, two different mechanisms. (1) OpenAI-style function calling is the chat-completions feature; the README documents `parallel_tool_calls`: “Whether to enable parallel/multiple tool calls (only supported on some models, verification is based on jinja template).” (2) `--tools` is a separate experimental built-in agent toolset for the Web UI: “start the server with `--tools all`.” Help text lists `read_file, file_glob_search, grep_search, exec_shell_command, write_file, edit_file, get_info` and says “do not enable in untrusted environments.” MCP is additional, stdio only (`--mcp-servers-config`), from `#26062`. The internal `GET /tools` route is marked “Please do NOT use this endpoint in a downstream application.” — same README
- Context, slots, keys, quoted from the generated help table:
  - `-c, --ctx-size N` — “size of the prompt context (default: 0, 0 = loaded from model)” (env `LLAMA_ARG_CTX_SIZE`)
  - `-np, --parallel N` — “number of server slots (default: -1, -1 = auto)” (env `LLAMA_ARG_N_PARALLEL`)
  - `--api-key KEY` — “API key to use for authentication, multiple keys can be provided as a comma-separated list (default: none)” (env `LLAMA_API_KEY`)
  - `--api-key-file FNAME` — “path to file containing API keys, one per line; lines starting with a hash are treated as comments (default: none)”
  - `--host HOST` — “IP addresses to listen on, comma-separated, or UNIX socket paths ending in .sock” (default `127.0.0.1`)
  - `--port PORT` — “port to listen (default: 9931)”
- Router startup, quoted: “To start in router mode, launch `llama-server` **without specifying any model**” (`llama-server` with no `-m`). Sources: `LLAMA_CACHE`, `--models-dir`, `--models-preset`. “By default, the router only limits the number of loaded models (`--models-max`, least recently used first).” `--models-max N` “default: 4, 0 = unlimited.” `--models-memory-margin N` unloads LRU models until the new one fits. Preset args example in the README: `llama-server -ctx 8192 -n 1024 -np 2`. Chat field: “`model`: (Required in router mode) The model name, used to route the request to the right instance. Ignored in single model mode.” — same README
- v0.8.0 changelog also records “server: add router device memory margin parameter for dynamic unloading (`#21231`).” — [v0.8.0](https://github.com/ggml-org/llama.cpp/releases/tag/v0.8.0)

### Inferences

- A drop-in OpenAI client points at `http://127.0.0.1:9931/v1` and can call chat completions and, with a pooling model, embeddings. Nothing in the docs requires an API key until the operator sets `--api-key`.
- One `llama-server` process in inference mode is one GGUF. Several models means router mode, which the dev doc describes as multiple inference instances behind one endpoint, not one process holding every model in a single context.
- `llama serve` and `llama-server` are both current. The former is the installer’s command in the root README; the latter is the CMake target and the binary the server README runs.

## Limits versus LM Studio: auth, bind, CORS, model ids, several models

### Takeaway

`llama-server` can be the local OpenAI-compatible engine on Linux and Windows: chat, embeddings, tools, optional API key, configurable bind, parallel slots, and a router that loads more than one model. It does not behave like a single LM Studio process that keeps a library of models hot under friendly ids. Defaults are open: no API key, bind localhost only, CORS `*`, and the model id is the file path unless `--alias` is set.

### Cited Findings

- Auth is off unless configured. `--api-key` default “none”; repeat keys as a comma-separated list. `--api-key-file` is one key per line. The server README’s public-deployment row says “set an API key, put the server behind a reverse proxy.” There is no documented user account or admin password. — [tools/server/README.md](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)
- Bind: `--host` default `127.0.0.1`; `--port` default `9931`. `--host` may be a comma-separated list of TCP addresses or UNIX socket paths ending in `.sock` (since v0.5.0, `#28690`). Overlapping addresses are “undefined behavior.” `::` “binds IPv6 only.” Reaching the LAN means passing something like `--host 0.0.0.0` yourself; the default does not. — same README; [v0.5.0](https://github.com/ggml-org/llama.cpp/releases/tag/v0.5.0)
- CORS: `--cors-origins ORIGINS` “comma-separated list of allowed origins for CORS (default: *)”; the special value `localhost` “reflect[s] the Origin header only if it is localhost.” `--cors-credentials` default enabled, and the README notes that with origins `*` the Origin header is echoed so credentials are allowed. Turning on `--tools` or `--agent` changes the default to `localhost`. Recommended table: public = API key plus reverse proxy; LAN = set `--cors-origins` to the frontend origin; same machine = `--cors-origins localhost`. — same README, rationale in [#25655](https://github.com/ggml-org/llama.cpp/pull/25655)
- Model identifier: “By default, model `id` field is the path to model file, specified via `-m`. You can set a custom value for model `id` field via `--alias` argument. For example, `--alias gpt-4o-mini`.” `--alias STRING` is “set model name aliases, comma-separated (to be used by API).” In router mode the `model` field is required and selects the instance; “Ignored in single model mode.” Some router endpoints want `?model={model_id}` and return 400 “model name is missing from the request” otherwise. — same README
- Several models: inference mode is “a single loaded GGUF model.” Router mode is a parent that forwards to child servers. Start it by omitting `-m`, or pass `--models-dir`. `--models-max` default 4 (0 = unlimited), LRU. `--models-memory-margin` adds a device-memory limit. Loading is not the same as LM Studio’s in-process multi-model picker: the dev doc says “multiple inference server instances.” Adding an HF model to the cache with `llama-server -hf …` requires a restart: “The server must be restarted after adding a new model.” — [tools/server/README.md](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md), [README-dev.md](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README-dev.md)
- v0.7.0 moved the listen port from 8080 to 9931. Clients and docs that still assume `:8080` are on the old default, except Docker images, which the v0.7.0 notes say still use 8080 inside the container. — [v0.7.0](https://github.com/ggml-org/llama.cpp/releases/tag/v0.7.0)

### Inferences

- As a local engine in the LM Studio role, the matching shape is: one `llama-server` (or `llama serve`) per machine, `--alias` set to the role name clients expect, `--api-key` set if anything other than localhost will connect, `--host` left at `127.0.0.1` unless the LAN should see it, and `--cors-origins` tightened if a browser on another origin will call it. Parallel requests are `-np`, not extra model loads.
- Serving chat and embeddings together is a poor fit for one inference-mode process: `--embedding` “restrict[s] to only support embedding use case,” and `/v1/embeddings` requires a non-`none` pooling type. Two roles means two processes, or router mode with two models.
- The web UI is enough to chat in a browser. It is not a native Linux app with LM Studio’s model browser, downloads, and runtime picker. Router mode plus the web UI’s model manager (called out in the v0.7.0 and v0.8.0 notes) is the in-tree substitute, and it still starts and stops child servers under `--models-max`.

### Gaps

- No side-by-side test against an LM Studio server was run, so request-body incompatibilities (tool-call deltas, `response_format` schema shape, logprobs, vision part types) are not enumerated beyond what the server README already qualifies: “While no strong claims of compatibility with OpenAI API spec is being made.”
- Whether router children inherit `--api-key` was not fully traced. v0.5.0 says “Do not pass log file or API key file to router-spawned children” (`#29212`, `#28938`). Treat child auth as something to verify before relying on it.
- SSL exists (`--ssl-key-file`, `--ssl-cert-file`, cmake `-DLLAMA_OPENSSL=ON`) but was not compared with LM Studio’s TLS story.
