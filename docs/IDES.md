# Editors: Zed and aider

Two tools, deliberately. They are good at different halves of the work and both
address roles rather than model names, so neither needs touching when a model
changes.

| | aider | Zed |
|---|---|---|
| Where | terminal | editor |
| Unit of work | a diff you approve | inline edits and agent runs |
| Best for | changes you want to review before they land | exploring, refactoring in place |
| Agent | n/a — it always shows you the diff | yes, with restrictable tools |

---

## aider

### Config

```yaml
# ~/.aider.conf.yml
# Roles, not model names. OPENAI_API_BASE + OPENAI_API_KEY come from
# scripts/aliases.zsh per invocation. One local model (ADR 0016, D1).
model: openai/local-main
weak-model: openai/local-main
dark-mode: true
auto-commits: true
map-tokens: 4096
```

`weak-model` is used for commit messages and summaries. With one resident
model there is nothing cheaper to point it at, and nothing to evict.
`ask-cloud` overrides both with the Gemini id from `config/roles.tsv`, so a
cloud session never sends its commit messages anywhere else.

### Architect mode

aider can split planning from editing. With one local model both sides are
`local-main`; the value left is that the design step stays visible.

```bash
ask-arch    # aider --architect --model openai/local-main --editor-model openai/local-main
```

`ask-deep` runs aider on `local-deep`, a slower, more careful model, swapped
in for that session only (ADR 0020). It unloads `local-main` while it runs:
beside a busy `local-main` the two passed the memory ceiling and `local-main`'s
requests timed out. It is also in Zed's model picker, labelled "load first":
with JIT off, a request to an unloaded role is answered by whatever is loaded,
without saying so. To use it from Zed, run
`scripts/demand-load.sh local-deep up --evict` on the host, and
`scripts/demand-load.sh local-deep down` when done (that brings `local-main`
back). While it is swapped in, Zed's `local-main` slots are answered by
`local-deep`.

### Switching mid-session

```
/model openai/local-main       the only local role
                              (cloud: quit and start `ask-cloud` instead —
                               it uses its own key and endpoint)
/ask                          question without editing anything
/architect                    toggle architect mode
```

`/ask` is worth the habit — it answers without proposing a diff, which keeps you
deciding what to change.

### Deliberate review

You have `auto-commits: true`, which is convenient and also the setting most
likely to let a change land without you reading it. For anything touching
flagged sensitive code:

```bash
aider --no-auto-commits
```

## Zed

### Point it at LM Studio

Directly in `~/.config/zed/settings.json` (ADR 0016). Every model slot —
agent, inline assistant, commit message, thread summary, compaction,
subagent — is `hearth/local-main`, so nothing ever asks for a second model.
**No cloud provider on this host (D3)**: cloud is `ask-cloud` in a terminal.

```json
{
  "agent": {
    "default_model":          { "provider": "hearth", "model": "local-main" },
    "inline_assistant_model": { "provider": "hearth", "model": "local-main" },
    "commit_message_model":   { "provider": "hearth", "model": "local-main" },
    "thread_summary_model":   { "provider": "hearth", "model": "local-main" },
    "compaction_model":       { "provider": "hearth", "model": "local-main" },
    "subagent_model":         { "provider": "hearth", "model": "local-main" },
    "auto_compact":           { "enabled": true, "threshold": 110000 }
  },
  "language_models": {
    "openai_compatible": {
      "hearth": {
        "api_url": "http://127.0.0.1:1234/v1",
        "available_models": [
          { "name": "local-main", "display_name": "<written by scripts/zed-sync.sh>", "max_tokens": 131072 }
        ]
      }
    }
  }
}
```

Automatic compaction runs at 110,000 tokens. The loaded window is 131,072.
Past that the server refuses the prompt, and Zed compacts on that error.
110,000 leaves about 21,000 tokens for the turn that crosses the line and
for Zed's count running behind the server. Zed's default of 90% (about
118,000) sits inside that lag. Compaction summarizes the older turns, sends
that summary plus the recent turns, and leaves the original thread in the
panel under **Context Compacted**. `/compact` does the same by hand.
**New From Summary** starts a fresh thread from it. The summary replaces the
cached prefix, so the next turn reads the new thread from the start.

`name` is the role and is what Zed sends. `display_name` and `max_tokens`
are generated by `scripts/zed-sync.sh` from `config/roles.tsv` + `lms ls`
(e.g. `local-main · <model> <quant>`), and `scripts/lms-load.sh` re-runs it
after every load, so the picker always shows what is actually loaded and the
window always matches the load context. Preflight warns if they drift. Add a
new role's entry by hand once; the sync keeps it current.

The token goes in through the UI (Agent panel → settings → `hearth` → API
key) so it lands in the keychain rather than a dotfile. Use the host token on
this machine; each laptop gets its own (phase 4).

### MCP example: auslaw

`auslaw` is not installed. `docs/MCP.md` uses its former setup as a worked
example: a reviewed stdio child, no jade cookie, seven AustLII tools exposed
only in a Research profile, and confirmation before each call.

Zed's built-in **Write** profile sets `enable_all_context_servers: true`
(Zed 1.26 defaults), which would expose any configured server in an ordinary
thread. Settings must redefine Write with that set to `false`. A profile
override **replaces** the built-in profile (`name` is required, tools are not
merged), so the override must carry the full intended tool list. Re-check
Write and Ask after a Zed upgrade: a partial override can fail the whole
settings load. `tool_permissions.default` is `confirm`, so each MCP call asks
first.

If auslaw is restored, switching to Research is the act of saying "this query
goes to AustLII." Follow the prerequisites, UI fields, JSON profile and checks
in `docs/MCP.md`; do not infer a command from this document.

Write and Ask set `fetch` and `search_web` to false. Zed's built-in Ask
profile includes both, so Ask is overridden here the same way Write is.
Web search is the Web profile.

### MCP: searxng, Web profile only

`searxng` is a `context_servers` stdio entry for the pinned SearXNG MCP
server (`docs/MCP.md`, ADR 0022). Its search tool sends the query text through
the host's SearXNG to public engines, so it is enabled **only** in the `web`
agent profile, and only `searxng_web_search` — `web_url_read` (any URL) and
the other two tools stay off. The profile's built-in `tools` map is empty:
no file reads, no edit, no terminal. Its `default_model` is
`hearth/local-main`. Each tool call asks first.

Switching to Web is the act of saying "this query goes to the search engines".
Never on client work.

### On a laptop

Through an SSH tunnel to the host — `docs/LAPTOP.md`. Zed points at
`http://127.0.0.1:1234/v1` exactly as on the host (the tunnel's local end),
with the **laptop's own** token. Run `ai-tunnel` before opening Zed. A Gemini
provider is allowed on the laptop (D3). The Web profile stays on
`hearth/local-main`; do not switch that profile to Gemini.

Zed's SSH remote projects also work: edit files on the host over SSH while
the model call goes through the tunnel. That needs a normal SSH key, not the
tunnel-only one.

### Agent profiles — the reason Zed is here

Zed's agent has **profiles with configurable tool access**. You can define one
that reads and proposes but cannot apply edits or run commands, and a separate
one that can.

That is the closest thing shipping today to an assistant that helps without
taking over, and it is why Zed earns its place over JetBrains here — JetBrains
only supports chat on local models.

Suggested split:

- **explore** — read files, search, discuss. No edits, no terminal. Use when you
  are trying to understand something.
- **build** — full tools. Use when you already know what you want.

The distinction is not about safety. It is about which mode you are in.

## Why two tools, and why this matters

The 2026 research on AI-assisted development is not comfortable reading.
Developers using AI assistance scored **17% lower on comprehension** afterwards,
with the steepest decline among those who fully delegated (Shen and Tamkin,
2026). The framing that stuck is **output up, capability down** — and the
distinction between *atrophy*, losing skills you had, and *foreclosure*, never
building them. Roughly half of programmer actions in LLM-assisted workflows show
identifiable cognitive bias, mostly anchoring on whatever the model proposed
first (Zhou et al., 2026).

Nothing ships to address this. The one paper directly on it —
[Agents That Teach](https://arxiv.org/html/2607.06101) — is a design proposal,
not a product. The measurement is years ahead of the tooling.

So the mitigations here are choices, not features:

- **aider shows a diff and waits.** That is friction, and the friction is the
  point. `/ask` and `--no-auto-commits` add more when you want it.
- **Zed's explore profile can't edit.** Reading and discussing without the option
  to apply keeps you deciding.
- **Local models are weaker, and that is quietly protective.** A model that
  cannot one-shot the answer keeps you in the loop — the opposite of how model
  quality is usually discussed.
- **Architect mode separates deciding from typing**, which keeps the design
  decision visible instead of buried in a diff.

None of this is about distrusting the output. It is about noticing when you have
stopped thinking, which by definition is not something you notice.

## Other editors

Not recommended here, recorded so the question does not come round again.

| Editor | State |
|---|---|
| JetBrains | Native LiteLLM support, free tier, but **chat only** on local models — no agent, no next-edit |
| VS Code + Continue | Works fully, but an extension rather than built in |
| Cursor | Not used here — rejects non-HTTPS base URLs; agent mode unreliable with custom endpoints |
